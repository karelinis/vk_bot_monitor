# 🤖 vk_bot_monitor — ESP32 IoT Bot

[![PlatformIO](https://img.shields.io/badge/platformio-ESP32-blue.svg)](https://platformio.org/platforms/esp32)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

> **Разработано при помощи DeepSeek V4 Pro 9B**

Умный IoT-бот на ESP32, который собирает данные с датчиков температуры, влажности и атмосферного давления, а также взаимодействует с пользователями через мессенджер VK.

---

## 🚀 Возможности

- **Мониторинг датчиков** — AHT20 (температура/влажность) + BMP280 (давление)
- **Wake On LAN (WoL)** — пробуждение до 32 устройств по MAC-адресам
- **Дистанционное управление** — перезагрузка устройства через голосовые команды
- **Long Poll уведомления** — мгновенная реакция на сообщения от пользователей
- **Автоматические уведомления** — отправка статуса запуска администраторам
- **Настройки через JSON** — конфигурация хранится в `config.json` на файловой системе LittleFS
- **Безопасное соединение** — HTTPS API VK + клиентский SSL

---

## 📋 Последние изменения

- **Обновление библиотеки WoL** — теперь используется `a7md0/WakeOnLan` v1.1.6 для более стабильной отправки магических пакетов. Поддерживает массив до 32 MAC-адресов.
- **Множественные WoL устройства** — конфигурация массива `wol_mac_addresses` позволяет пробуждать несколько устройств одновременно с задержкой 50мс между пакетами для избежания интерференции.
- **Улучшенная архитектура** — переписана схема проекта для наглядности потоков данных и взаимодействий компонентов.

## 🛠️ Конфигурация

Создайте файл `config.json` в корне проекта (или на LittleFS при первом запуске):

```json
{
  "wifi_ssid": "ваш_ssid",
  "wifi_pass": "пароль",
  "vk_token": "ВАШ_ТОКЕН_ВК",
  "group_id": "123456789",
  "admin_peer_ids": [
    -123456789,
    -987654321
  ],
  "i2c_sda": 21,
  "i2c_scl": 22
}
```

### Поля конфигурации:

| Поле | Тип | Описание |
|------|------|----------|
| `wifi_ssid` | string | Имя Wi-Fi сети |
| `wifi_pass` | string | Пароль Wi-Fi |
| `vk_token` | string | API-токен VK для доступа к сообществу |
| `group_id` | string | ID сообщества VK |
| `admin_peer_ids` | array | Массив ID пользователей, которым отправляются уведомления |
| `i2c_sda` | int | Pin для линии данных I2C (по умолчанию 21) |
| `i2c_scl` | int | Pin для линии тактового сигнала I2C (по умолчанию 22) |

## 🚦 Жизненный цикл

### При старте устройства:

1. **Загрузка конфигурации** — читает `config.json` с LittleFS
2. **Инициализация I2C** — настраивает пины SDA/SCL
3. **Проверка датчиков** — пытается подключиться к AHT20 и BMP280
4. **Wi-Fi подключение** — соединяется с сетью из конфигурации
5. **Long Poll соединение** — получает сервер Long Poll от VK API
6. **Уведомление админов** — если датчики работают корректно, отправляет приветственное сообщение

### В цикле работы:

- Постоянно проверяет Long Poll сервер
- При получении нового сообщения:
 - Если содержит слово "датчик" → отправляет текущие показания
 - Если содержит "перезагрузка" → отправляет статус и перезапускает ESP32

## 🔬 Логика работы с данными

### AHT20 (температура/влажность)
- Проверяет подключение по I2C-адресу `0x38`
- Отображает значения только если они в диапазоне `-50.0°C` – `100.0°C`
- Выводит предупреждение при сбоях

### BMP280 (атмосферное давление)
- Проверяет подключение по I2C-адресам `0x76` или `0x77`
- Переводит давление из Па в мм рт. ст.
- Отображает только если давление в диапазоне `300` – `900` мм рт. ст.

### Пример вывода данных:
```
📊 Данные с датчиков:

🌡 Температура: 22.3 °C
💧 Влажность: 55.7 %
🎈 Давление: 760.2 мм рт. ст.
```

## 📡 Long Poll реализация

- Использует `wait=25` для уменьшения частоты запросов
- При получении ошибки Long Poll сбрасывает сервер и пытается переподключиться
- `failed` в ответе VK — полная потеря соединения, сервер сбрасывается

## 📝 Ключевые особенности реализации

### 1. URL-кодирование
Функция `urlEncode()` корректно кодирует специальные символы в URL, используя стандартный алгоритм с поддержкой `alphanumeric`, `-`, `_`, `.`, `~`.

### 2. Проверка физических реалистичностей
- Температура AHT20 должна быть в диапазоне `-50.0°C` – `100.0°C`
- Давление BMP280 должно быть в диапазоне `300` – `900` мм рт. ст.
- Эти проверки защищают от сбоящих данных при плохом питании

### 3. Обработка ошибок I2C
Функция `isI2CDeviceConnected()` проверяет физическое присутствие устройства на шине I2C, что надёжнее, чем просто успешная инициализация библиотеки.

### 4. Умная инициализация датчиков
BMP280 пытается подключиться к обоим возможным адресам (`0x76` и `0x77`), так как некоторые прошивки используют разные дефолты.

### 5. Защита от повторной отправки boot-сообщения
Переменная `isBootMessageSent` гарантирует, что приветственное сообщение отправляется только один раз при старте.
